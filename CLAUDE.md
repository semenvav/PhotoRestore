# photo-restore

Сервис реставрации семейного фотоархива: сервер (`server/`, FastAPI в Docker) + агент на ПК
(`agent/`, Windows, ComfyUI). Полное ТЗ — `docs/SPEC.md`, этапы — §11. ТЗ есть только локально
(в `.gitignore`): в нём детали домашней сети.

Репозиторий публичный: в коммитах не должно быть хостов, адресов, путей и имён устройств
домашней сети — только плейсхолдеры и переменные (`RESTORE_HOST` и т. п.).

## Команды

```sh
uv sync                                   # зависимости (workspace: корень + server/ + agent/)
uv run pytest -q                          # тесты (сервер, протокол, агент с FAKE_COMFY)
uv run ruff format server agent tests && uv run ruff check server agent tests
uv run mypy                               # типы (server/app, agent/restore_agent)
# локальный сервер: скопируйте .env.example в .env (AGENT_TOKEN — для API агента;
# GEMINI_API_KEY — платный Gemini, FAKE_GEMINI=1 — без него; FAMILY_HOST=127.0.0.1 —
# тогда http://127.0.0.1:8000 открывается как отец, http://localhost:8000 — как владелец)
uv run uvicorn --factory app.main:create_app --reload --app-dir server
# агент: config.toml по образцу agent/config.example.toml; FAKE_COMFY=1 — без GPU
uv run python -m restore_agent --config agent/config.toml
# новая миграция после правки models.py:
DB_PATH=var/gen.db uv run alembic -c server/alembic.ini upgrade head
DB_PATH=var/gen.db uv run alembic -c server/alembic.ini revision --autogenerate -m "..."
```

Сборка образа: `docker build -f deploy/Dockerfile .`; пример стека — `deploy/compose.yaml`.
Агент на ПК ставится `agent/install.ps1` (venv + задача Планировщика при входе, без окна; из
рабочей копии), обновляется `agent/update.ps1` (сборка, которая работает на сервере, с GitHub).

## Версии и CI

- `.github/workflows/ci.yml`: каждый push — ruff, mypy, pytest; прошедший push публикует образ
  `ghcr.io/semenvav/photo-restore` (теги `latest` = ветка по умолчанию, `<ветка>`, `sha-…`).
- Номер сборки: серия из файла `VERSION` = номер этапа (`0.1` — M1, `0.2` — M2…). Первая сборка
  ветки по умолчанию в серии получает номер `0.1`, следующие — `0.1.1`, `0.1.2`… Номер ставится
  git-тегом `v…` после публикации образа и передаётся в образ как `APP_VERSION`
  (виден в шапке и в `/healthz`).
- **Начиная новый этап, первым делом поменять `VERSION`** (сейчас `0.5` — M5, последний этап ТЗ).
- Версия агента — `agent/restore_agent/__init__.py`; сервер принимает агентов не старше
  `MIN_AGENT_VERSION` (`server/app/api/agent.py`), иначе `hello` → 426. Несовместимая правка
  протокола = поднять обе.

## Инварианты

- `original.*` никогда не открывается на запись после приёма (файл в `store/` с правами 0444).
  Варианты (`variants/vNNN.png`) тоже 0444 и не перезаписываются.
- Статус фото меняется только через `states.transition()`; события истории — `states.log_event()`.
- Агент не получает задач без активного `run` (`runs.claim`).
- Все пути внутри `store/` строятся из ID (`storage.Store`), имена от пользователя в пути не попадают.

## Решения, которых нет в ТЗ

- Файлы во «Входящих» после приёма остаются на месте; таблица `inbox_file` помнит
  (путь, размер, mtime_ns) принятых файлов. Новый файл по тому же пути — новое фото.
- Не принятый файл переносится в `inbox/_unsupported/` (событие `unsupported`). Уведомление
  на доске видно неделю и только пока файл там лежит; «Скрыть» запоминает ID последнего
  показанного события (настройка `notices_dismissed`), новые снова видны.
- `photo.sha256` уникален частичным индексом `WHERE duplicate_of IS NULL`: у дубля тот же хеш.
- Приём копирует файл в `store/.staging/`, считая sha256 по записанным байтам, проверяет его
  Pillow и только потом переносит в `store/R-xxxx/original.<ext>`. Если каталог для нового ID
  уже существует (сбой до commit, БД из бэкапа), он переносится в `store/.orphans/`.
- `photo.width/height` — размеры после EXIF-транспонирования.
- Кроп: `crop` задаётся как `cropper.getData()` (cropper.js 1.x) — в пикселях оригинала внутри
  описанного прямоугольника изображения, повёрнутого на `rotate90·90° + angle` по часовой.
  Сервер повторяет эту геометрию одним аффинным преобразованием (`imaging.prepare`),
  углы вне изображения заливаются белым. «Без обрезки» = `crop: null`, поворот сохраняется.
- Время в БД — UTC; показывается в `DISPLAY_TZ`.
- Форматы: jpg, png, webp, tif, avif (`storage.ALLOWED_EXT`). AVIF читает Pillow (libavif в
  wheel); его irot/imir Pillow отдаёт как EXIF-ориентацию. HEIC не поддерживается.
- Удаление фото (`app/deletion.py`, по просьбе владельца, вопреки «не удаляется» из ТЗ — но
  без потери файлов): из БД уходят фото, варианты, задачи и история, в общей истории остаётся
  событие `deleted`; каталог `store/R-xxxx` переносится в `store/.deleted/`, чистится вручную.
  `inbox_file` остаётся без `photo_id`, поэтому файл во «Входящих» повторно не принимается.
  Фото в обработке (`EDITING`, `UPSCALING`, `GEMINI`) не удаляются. Дубли удалённого
  основного остаются: основным становится первый, остальные ссылаются на него. ID не
  переиспользуются (`sqlite_autoincrement`). В UI удаление — только через диалог подтверждения.
- Workflow `workflows/edit_qwen2511.json` собран по шаблону ComfyUI (графов из инструкции в
  репозитории нет): Qwen-Image-Edit-2511 fp8mixed + Lightning LoRA 8 шагов, cfg 1, euler/simple,
  shift 3.1. `IN_STEPS` — отдельный `PrimitiveInt` (поле `value`): у узла один заголовок, а
  KSampler занят под `IN_SEED`. Свой граф из ComfyUI можно положить вместо этого, сохранив
  заголовки; реестр проверяется при старте сервера.
- Привязки в задаче агента — с полями: `{"image": {"node", "field"}, "seed": {...},
  "output": {"node"}}`. Сервер подставляет prompt/steps/megapixels, агент — вход и seed.
- Запуск `scope=all` берёт и задачи, созданные после старта. `job.run_id` — запуск, в котором
  задачу взяли последний раз (для прогресса). Запуск завершается при `claim` → 204, после
  `complete` и в фоновой проверке (`main.sweep`, раз в `SWEEP_INTERVAL_S`; она же возвращает
  задачи с истёкшей арендой).
- «Отменить» задачу: она `cancelled`, фото остаётся (взятая — возвращается) в статусе ожидания
  своей стадии с флагом `attention`; дальше «Повторить» (новая задача с тем же заданием) или
  «Отложить». Новых переходов нет. Неудача после 3 попыток или `retryable: false` — так же.
- Выходы до `complete` лежат в `store/R-xxxx/jobs/<job_id>/`; при `complete` копируются в
  `variants/vNNN.png` (номер — по файлам), превью `cache/preview_vNNN.jpg`, `thumb_vNNN.webp`;
  после commit каталог задачи удаляется.
- Просмотрщик проверки — свой код (`static/review.js`) вместо img-comparison-slider/panzoom:
  зум и сдвиг общие для всех панелей, разделитель двигается только за ручку (иначе
  перетаскивание конфликтует со сдвигом).
- Агент загружает вход в ComfyUI как `input/restore/source.png` (overwrite); результаты
  SaveImage копятся в `ComfyUI/output/restore/` — агент их не трогает (удаляет только своё в
  workdir).
- Модели выгружаются (`/free`, один раз) и после `claim` → 204, и когда запуск остановлен
  («Стоп» посреди задачи: она доделывается, потом выгрузка).
- ComfyUI агент поднимает снова, если тот упал или его закрыли (не чаще раза в
  `COMFY_RELAUNCH_PAUSE_S`); пока запущенный агентом процесс жив, второй не запускается.
  Поэтому `comfy_launch_cmd` должен жить столько же, сколько ComfyUI (не `.bat` с `pause`).
- `config.toml` перечитывается на лету (пульс, по mtime+размеру): адрес и токен — сразу
  (новый httpx-клиент в `ServerClient.http`), другой ComfyUI — между задачами, `workdir` —
  только перезапуском; файл с ошибкой не применяется. Вызовы по задаче при 401 повторяются,
  пока не исправят токен. Остальные 4xx посреди задачи не роняют агента: `fail`, результаты
  остаются в workdir; цикл агента ловит любые исключения и пишет их в лог.
- Обновление агента: `update.ps1` → `python -m restore_agent.update`: номер сборки из
  `/healthz` сервера (у сборок не из ветки по умолчанию номера нет — тогда `-Version`), архив
  тега `v<номер>` с GitHub, `pip install …/agent` в `agent\.venv` при остановленной задаче
  Планировщика. `install.ps1` ставит из рабочей копии и перезапускает работающего агента.
- Апскейл — нативный SeedVR2 ComfyUI (`comfy_extras/nodes_seedvr.py`), граф
  `workflows/upscale_seedvr2.json` по шаблону «SeedVR2 7B Upscale Image» с моделями fp16 и
  коррекцией цвета `lab` (тональность входа). `IN_UPSCALE` — `ResizeImageMaskNode`, поле
  `resize_type.multiplier` (множитель, а не разрешение): масштаб считает сервер
  (`jobs.auto_scale`: до `target_mp` из настройки «upscale», не больше `max_scale`, не меньше
  ×1); «Переделать апскейл» — модель и масштаб из `jobs.UPSCALE_SCALES`. Параметр реестра с
  `choices` (ключ → значение в графе): настройки и UI хранят ключ (`7b_fp16`). Сервер не
  стартует без workflow для `edit_local` и `upscale_local` (`workflows.REQUIRED_TYPES`).
- Финал (`final.py`): `accepted_variant_id` — принятый вариант, `final_variant_id` — что
  отдаётся. Результат апскейла сразу становится финалом; «Без апскейла» делает финалом
  принятый, не меняя статус; «Утвердить» отдаёт выбранного кандидата (принятый или его
  апскейл); «Назад к вариантам» обнуляет оба поля.
- Отдача (`delivery.py`): `delivered/<альбом>/<имя>_restored.png`, занято другим фото —
  `<имя>_restored_R-0042.png`; чей файл — по PNG-метаданному `Title`, повторная отдача того же
  фото перезаписывает свой файл. PNG не перекодируется: чанки копируются, текстовые чанки
  ComfyUI (граф, промпт) выбрасываются, наши — `Title` (ID), `Source` (исходное имя),
  `Restored` (дата в `DISPLAY_TZ`), `Software` — пишутся перед IDAT (не-latin-1 — iTXt).
  Запись атомарная; путь — в `photo.delivered_path` (для возврата отцом в M5).
- Массовые действия: «Утвердить финал» (каждое фото — своя транзакция), «Поднять приоритет»
  (задачам в очереди — максимум по очереди + 1), «Отменить задачи» (`jobs.cancel` для всех
  активных). `FAKE_COMFY` увеличивает картинку на `resize_type.multiplier` из графа.
- Gemini (`gemini.py`): google-genai, `generateContent` (API v1), свой `httpx.AsyncClient` в
  SDK (иначе берёт httpx2; так respx подменяет API в тестах). Модели ноября 2026 — без
  `-preview`: `gemini-3-pro-image` (по умолчанию), `gemini-3.1-flash-image`,
  `gemini-nano-banana-2.1`. «В Gemini»: `REVIEW → GEMINI` и задача `edit_gemini` без `run`;
  воркер в lifespan (`max_concurrency` ≤ 2) возвращает фото `GEMINI → REVIEW` (система): с
  вариантом `gemini` или с `attention` и текстом отказа (`finish_reason`, `block_reason`,
  текст ответа). Повторы: 429, 5xx, обрыв — до 3 с паузой `GEMINI_RETRY_BASE_S`·2ⁿ (2, 4, 8 с);
  остальные ошибки и отказ — сразу. Аренды у задач Gemini нет: взятые до перезапуска
  `recover()` возвращает в очередь. «Отменить» задачу Gemini — фото сразу на проверку с
  флагом; ответ уже идущего запроса выбрасывается, цена учитывается.
- Вход Gemini — JPEG q95, длинная сторона ≤ 3072 (вход стоит фиксированно); с образцом —
  `prepared`, затем источник, промпт по шаблону ТЗ §8 (пустой текст — базовый пресет); без
  образца (источник — `prepared`) — базовый пресет + текст. Пропорции: ближайшая из 10 общих
  для всех моделей, ответ обрезается по центру под вход; > 2% — `params.cropped`. Берётся
  первая картинка ответа не из мышления (`part.thought`).
- Стоимость = `usage_metadata` × цены из настройки `gemini_prices` ($/1 млн токенов: вход;
  текст и мышление; картинка; без разбивки по модальностям весь выход с картинкой — по цене
  картинки) → `job.cost_usd` (отказы и отменённые тоже) и `variant.cost_usd`. Бюджет месяца =
  сумма `job.cost_usd` задач Gemini, созданных с 1-го числа в `DISPLAY_TZ`. Отправка
  блокируется, если потрачено ≥ бюджета или потрачено + «в работе» × оценка + новые × оценка >
  бюджета; массовая — целиком. Оценка — среднее по 20 прошлым запросам той же модели и
  размера, иначе по ценам; нет цен для модели — отправка заблокирована.
- `FAKE_GEMINI=1`: вход с пометкой, цена 0; промпт с `FAKE_REFUSE` — отказ `IMAGE_SAFETY`.
- Настройки (`/settings`, `presets.py`): схемы pydantic `EditPrefs`, `UpscalePrefs`,
  `GeminiPrefs`, `Price`; сохранённый словарь дополняется значениями по умолчанию (новые
  ключи после обновления). Пресеты: один базовый + добавки (порядок `sort`, ↑/↓).
- Ручная правка: файл (jpg/png/webp/tif/avif) → EXIF-поворот, RGB 8 бит, PNG — вариант
  `manual` с `parent_id` выбранного, `REVIEW → REVIEW`. Любое следующее действие владельца
  (доработка, Gemini, правка, «Принять») снимает отметку `attention` (`jobs.clear_attention`).
- Роли (`auth.py`): входа нет. Отец — любой запрос с `Host` из `FAMILY_HOST` (через запятую,
  без порта и регистра; в compose — второй роутер Traefik на тот же сервис). Ему доступны
  только `/family…`, `/static/`, `/healthz`: GET → 303 на `/family`, остальное → 403.
  Остальные хосты — владелец; он видит `/family` как предпросмотр без кнопок. Без
  `FAMILY_HOST` отвечать за отца некому (в логе предупреждение).
- Экран отца (`family.py`, `api/family.py`): «Ждут ответа» (DELIVERED, по времени отдачи) и
  «Принятые»; «было» — `prepared`, «стало» — `final_variant_id`; картинки только через
  `/family/{id}/…` и только у этих двух статусов. Имя — исходное без расширения, `_` →
  пробел; R-ID, варианты, цены не показываются. Просмотрщик — тот же `review.js` (только
  «два рядом», кнопки «Было / Сравнить / Стало»).
- «Вернуть» (комментарий обязателен, ≤ 2000 знаков) → REVIEW от отца (раунд + 1),
  `family_comment`, `accepted_variant_id`/`final_variant_id`/`delivered_path` обнуляются.
  Копия из «Готово» удаляется, только если её `Title` — наш ID (пересохранённый или чужой
  файл остаётся); итог — в событии (`delivered_removed` / `_kept` + `reason` / `_missing`).
  Метка «↩ Отец» на доске и плашка на проверке — пока фото не отдано снова (на проверке —
  пока последний ответ отца — возврат); повторно отданное отец видит с «Вы просили: …».

## Устройство

- `server/app/main.py` — `create_app()`: реестр workflow (битый — сервер не стартует);
  lifespan: миграции, каталоги, настройки по умолчанию, циклы приёма и `sweep`.
- `intake.py` — опрос `inbox/`; `imaging.py` — Pillow; `prep.py` — подготовка;
  `jobs.py` — задачи (стадии, неудача, отмена, повтор); `runs.py` — запуски и `claim`;
  `results.py` — входы, выходы, `complete`; `workflows.py` — реестр `workflows/registry.yaml`;
  `final.py` — принятие и финал; `delivery.py` — отдача во «Готово»; `gemini.py` — Gemini
  (бюджет, отправка, воркер); `presets.py` — пресеты и пользовательские настройки;
  `auth.py` — роль по хосту; `family.py` — приёмка отцом.
- `api/ui.py` (доска, карточка, подготовка, файлы), `api/pc.py` (панель «ПК», запуски),
  `api/review.py` (проверка, доработка, Gemini, ручная правка, «Принять»), `api/final.py`
  (финал), `api/settings_page.py` (настройки), `api/family.py` (экран отца),
  `api/agent.py` (протокол агента). Просмотрщик — `templates/_viewer.html` + `static/review.js`
  на проверке и финале. Jinja2 + htmx +
  Alpine; JS-библиотеки лежат в `app/static/vendor/` (без CDN).
- `agent/restore_agent/` — `runner.py` (цикл, подъём ComfyUI, config на лету), `client.py`
  (сервер, повторы с паузой), `comfy.py` (HTTP API ComfyUI), `fake.py` (`FAKE_COMFY=1`),
  `wiring.py` (клиенты по конфигу), `config.py`, `update.py` (обновление с GitHub).
- Тесты: `tests/`; картинки генерируются в `tests/imgutil.py`; сквозной прогон агента —
  `tests/test_agent_e2e.py`.
